## 本次处理

Linux 的校验白名单补上 LICENSE，继续严格拒绝其他根目录项；不删除许可证、不放宽为忽略未知文件，也不改变实际打包内容。

macOS 签名设置按贡献者选择保持不变。仅记录原因，由维护者决定是否支持 PR 的无证书临时签名；当前未启用 CSC_FOR_PULL_REQUEST、未跳过签名验证、未使用正式证书或任何签名秘密。

Windows 未改动应用权限逻辑、HTML 预览或断言。独立的同一打包版本权限检查返回 BLOCKED；随后六个新建 HTML 预览分别点击检查，均返回 BLOCKED，控制台报告 Permissions policy violation。本机检查验证拒绝行为，但没有复现云端超时，因此尚不能给出其确定根因。

完整工作区复现曾被本机测试专用 Explorer 粘贴助手卡住，随后只结束该助手并由测试清理自身窗口；这次完整复现不能记为通过。权限定向检查使用独立资料，无剪贴板操作。原有用户窗口和会话不用于诊断。

## 后续核对

新的 PR 检查可确认 Linux 校验修正，并再次执行 Windows 原检查。若 Windows 仍在同处失败，应在云端测试中记录 iframe 的 document.readyState、点击处理函数绑定情况、输出内容及页面错误，再区分页面时序和权限请求完成问题；不能以增大超时或删掉 BLOCKED 断言代替诊断。

## 第二轮结果与终端测试修正

第二轮 [37897225888](https://github.com/noeigenstate/Agentrix/actions/runs/37897225888) 的 Linux x64、arm64 打包及桌面检查全部通过，Linux SSH 继续通过。macOS 保持原签名策略并仍在签名校验失败；发布任务正常跳过。

Windows 此轮停在更早的 smoke.mjs：REPORT_LINK 的 OSC 8 文件链接悬停超时，两次执行均相同，尚未进入 workspace-smoke.mjs 的麦克风权限检查。不能据此认定先前的权限超时已经解决。

定向检查在与云端相同的 1024×768 窗口中，排除展开动画后输出 OSC 8 链接，再延迟返回提示符。提示符造成终端滚动，链接从 y=621 移到 y=603。使用旧坐标得不到链接提示，重新测量后得到 Ctrl 提示并真实点击打开 HTML。这证明原测试只测量一次、随后静止等待的机制存在时序缺陷，能够导致此类超时；云端仍需复测确认。

修正仅将原有测量与悬停放入同一次轮询，沿用原超时，保留真实 Ctrl 点击、打开目标预览、普通点击不打开和会话保持的断言。独立打包版本的完整桌面回归通过，包括 OSC 8、相对文件、PNG 与换行网址链接、终端恢复、完成提醒和紧凑窗口检查。应用运行代码没有变化。

先前的 HTML 权限超时仍未复现。测试样本仅增加 CHECKING 标记与失败时记录 readyState/处理函数/结果，以便区分未触发点击和请求未完成；BLOCKED 安全断言保持原样。
