# 可选简洁外观与玻璃背景

在现有主题列表末尾增加浅色「黑白橙」与深色「白黑橙」。已同步上游 0.6.12（7be8797）。上游四套主题、默认晴空、默认终端配置与业务行为保持原方案；不移动原代码或重构会话、通知、文件、Git 和窗口交互逻辑。

## 两套简洁主题

- 浅色：雾白底色、黑字；深色：中性黑底色、白字。辅助文字为可读灰色；提醒与错误使用橙色。
- 通过字号、粗细、留白与下划线建立层级。普通工作和已查看结果保持中性，未读或错误保留橙色边缘与原状态文字。
- 阅读视图、文件列表、Git 状态与差异使用同一语言。Git 保留状态字母、+ / −、不同纹理和边线，分支图保留拓扑及虚线差别。
- 16 色 ANSI 的红色转为可读橙色，其余普通色转为中性；256 色采用灰阶。切回原主题恢复原调色板。
- 程序直接指定的 RGB 真彩色、背景和反色保持原输出，不改写助手的原生界面或终端缓冲区。

## 材质与背景联动

「界面材质」保持两个原选项：液态玻璃、实色。液态玻璃下新增「玻璃背景」：主题背景、桌面背景；两种背景均能配合六套主题。

主题背景保留应用壁纸与上游磨砂材质。桌面背景由系统模糊窗口背后的内容，每个面板只叠加透明底色，不再增加一层面板折射。实色模式隐藏背景选择，切回玻璃时记住原选择；透明度只调整底色，不调整正文透明度。标题栏和对话框保持易于操作的较实底色。

透明度默认跟随主题，可选择自定义。0% 不透明，100% 最透明；实色与系统减少透明度偏好优先。

桌面背景在六套主题中均可使用，因此保留为液态玻璃内部的背景选择，不单列第三种材质。

原生窗口在启动时准备；从普通窗口首次选择桌面背景显示重新打开提示，不自动重启、不重建用户窗口或终端。早期本地预览的 surface=desktop-glass 会迁移为液态玻璃 + 桌面背景。

## 字体与推荐配置

外观中新增终端字重，以及西文/中文字体名称输入与常用建议。西文选择本机已安装的等宽字体；中文作为西文缺字时的后备。留空严格使用上游原字体字符串。没有安装的字体继续使用后备顺序；自定义字体栈在中文后备之前增加 Linux 常见的 DejaVu Sans Mono/Liberation Mono，空值仍严格保持原字体栈；不下载或分发字体文件。字重默认沿用上游 500，可选 400 / 500 / 600；普通文字和程序加粗的语义保留。

同时补上 xterm 6.0 的 DOM 选区显示缓存清除：取消选区后调整主题/尺寸不再恢复旧高亮，实际选区与快捷键不变；通过守卫接入现有渲染适配入口，不修改依赖包。

字体、字重与主题各自按对应设置变化更新现有终端；字体变化重新计算尺寸，不重建会话、不清空输入、不重新应用主题调色板。

「应用推荐配置」仅在明确点击后调整外观。切换主题不会覆盖手动配置；推荐不会改动提醒、声音、会话恢复、快捷键等设置。

| 主题 | 字号/字重 | 字体 | 渲染 | 玻璃背景 | 透明度 |
| --- | --- | --- | --- | --- | --- |
| 晴空、林间光影、山青蓝、西野红 | 原方案 12 px / 500 | 原字体顺序 | GPU | 主题背景 | 跟随原主题 |
| 黑白橙 | 16 px / 400 | Cascadia Code + Noto Sans SC | 兼容 | 支持时桌面背景 | 25% |
| 白黑橙 | 16 px / 400 | Cascadia Code + Noto Sans SC | 兼容 | 支持时桌面背景 | 20% |

不支持桌面背景的平台推荐主题背景。推荐透明度按黑/白极端底色校验，普通终端文字保留至少 7:1 的理论合成对比度；用户仍可自行调整。字体观感与显示器/渲染方式相关，上述推荐基于本机对照，不保证所有设备的观感相同。

字体许可、实际元数据与分发边界见 [font-licenses.md](font-licenses.md)。当前包不含字体文件。

## 平台与窗口边界

Windows 11 22H2+ 接入 Electron acrylic；macOS 接入 under-window vibrancy；Windows 10 用隔离的 PowerShell/.NET 兼容助手调用 blur-behind，不增加原生 addon 或生产依赖。

本机 Windows 10 19045 已做实际背景窗口的模糊开/关像素对照。透明窗口支持最大化和窗口内展开，系统全屏暂不支持，设置中显示这一限制。Windows 11 和 macOS 的调用经过单元检查，但尚未进行实机验证；Linux 保留原背景。

Windows 10 透明窗口使用有黑白实体描边的光标，切换底色后继续保留，因为窗口本身的透明属性没有改变。原来的普通窗口、终端鼠标协议和链接光标保留原方案。已检查 Chromium 光标位图；此前用户物理光标消失的具体根因未被完整复现，不声称已确认所有设备上的问题。

## 验证入口

- npm test：设置持久化与迁移、推荐配置范围、对比度、字体名称校验、原调色板一致性及现有单元测试。
- npm run test:appearance：六主题 × 两种渲染 × 两种玻璃背景/实色，共 36 组；原生 RGB 表面、字体/会话/草稿、材料联动、推荐、文件预览、语言、重启与无字体下载。
- npm run test:monochrome；PROJECT_GRID_MONO_THEME=mono-amber-dark 运行深色：ANSI、提醒、阅读视图与 Git 差异。
- npm run test:question-appearance：真实隔离 PTY 输出 Codex/Claude 的提问、多选、审阅与填写样本，检查两套简洁主题的文字与表面。
- npm run test:readability：GPU/DOM 字重和字体实际识别、缺失字体回退、输入与节点保持、光标位图、普通窗口与原生窗口的光标范围。
- npm run test:glass-transparency：六主题透明度两端、默认恢复、展开面板、实色及减少透明度回退。
- npm run test:desktop-glass：真正背景的合成像素、窗口边界、冷启动与重启提示。屏幕捕获先校验自建窗口标识，防止其他窗口遮挡造成误判。

另运行原有的主题/Markdown、GPU、多终端、材质性能、输入、阅读、完成、Git、导航和窗口检查，并在独立 Windows 打包版本中再次执行 36 组组合。测试使用独立资料，不关闭、不重启或输入用户正在使用的会话。

较早的 Node 22 需要显式启用 --experimental-strip-types 来运行上游直接引用 TypeScript 的测试；不为本功能改动原测试启动规则。
